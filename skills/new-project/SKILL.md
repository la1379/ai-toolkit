# 做项目流程（省 token 版）

这是用户沉淀的做项目 SOP，提炼自桌面上 7 个已完成项目的 project.md。目标：**把 token 花在刀刃上**——能脚本干的零 token，Claude 只做必须人（模型）做的事。

## 什么时候用

- **新项目**：用户说"开新项目/做项目/帮我做XX" → 按完整流程走
- **旧项目延续**：先读该项目的 `project.md`（记忆中枢），按它的待办/已知限制继续，**不要重新探索**
- 用户说"按流程来/按套路" → 默认套用本流程

## 怎么读这个 skill（先看这 5 行）

- **主文件读完就够开工**；`references/` 是**按需读**，不要一上来整份拉进来。
- **踩坑池不是用来通读的** —— 扫一眼标题，遇到具体问题再查那一条。
- **怎么维护**：新坑先记进**当前项目的 `project.md`**；只有**跨项目通用**的才补进 `references/踩坑池.md`。
- **什么时候该拆**：某个 references 文件超过 ~60 行，或某个主题超过 ~10 条 → 拆成 `references/<主题>.md`，主文件加一行指路。
- **改了就要对账**：拆分/改名/搬家之后，**grep 所有 `详见 §X` / `见下` / 文件路径，逐个验证目标还在** —— 死链是搬迁的自带副作用（本 skill 拆完就查出 2 处）。

## 四条铁律（违反一次的代价就够呛）

**① 准入类项目先定「维度」，再写规则。**
先问"这个集合里应该只有什么"，而不是"哪些文件看起来该收"。归档项目在这上面栽了**四次**（关键词 → 归属权 → 流程产物 → 结构判据），每次都是用户先发现的。
关键词判得出「这是综测表」，判不出「这是**我的**综测表」；结构判据判得出「这是完整工程」，判不出「这是**我的**工程」。→ 详见 §2 的对照表。

**② 规则判不了归属时，让人拍板；别把规则调到完美。**
规则能判**类别**，人才能判**归属**。形态固定成：
`脚本按规则把候选做小 → 出「可勾清单」 → 用户删行 → 脚本可撤销地执行` → 详见 §2.5。

**③ 验证「结果是否安全」，不只是「动作是否正确」。**
干跑全绿也可能在误删 —— 归档项目里 `--dry-run` 一切正常，审计闸门却发现 8 个文件会被误删。→ 详见 §7 第 5 条。

**④ 一个会话一个任务，别让一轮对话承载太多。**
上下文压缩后**成本会回升、稳定性会下滑**：摘要丢细节，AI 绕回已经解决的问题；多任务挤在同一轮里还会「串线」—— 改新功能时把刚验收过的旧功能改坏。→ **任务级开新会话**，只喂当前任务相关的架构 / 模块文档 / 验收标准（同「按需读」）。**前提**：架构、模块边界、任务依赖先设计好（§1 骨架 + `project.md` 就是干这个的），否则窗口越多越乱。（B站 UP 主接单经验，2026-09）

## 流程（10 步 + 一个岔路 §2.5）

### 1. 骨架先行（开工第一件事）
新建项目文件夹，立即写 `project.md` 骨架（模板在 `references/project文档模板.md`），只填：一句话目标、交付物、目录结构、最后更新日期。它是整个项目的记忆中枢——下次会话读它就能恢复全部上下文，这是最大的 token 节省点。

### 2. 探索核实，一次问清
动手前把关键事实一次性核实完（用 Explore/Plan agent 或直接查，但**只查一次**，记录进 project.md）：
- 数据源/文件路径（精确到目录）
- 可复用资产：已有的脚本、模板、skill（各项目文件夹里翻）
- 回归基准：一个可断言的真值样例（数值/结构逐项比对用）
- 环境与工具链：Python 版本、已装的库（openpyxl/docx/pdfplumber/rapidocr…）、LibreOffice 路径（`D:\20260606-now app\libreoffice\program\soffice.exe`）、Electron、ps2exe 等
- 口径决策：任何"规则"在开工时和用户确认一次，写死，执行期不再问。**能早定的早定；依赖材料成型才好判断的（观感、篇幅、内容去留），到那个节点一次性问清，不零敲碎打**——每个问题仍只问一次

> **⚠️ 准入类项目（收集/筛选/归档/去重/合并）第一步不是写规则，是问「这个集合里应该只有什么」。**
> 先定**维度**，再写规则。维度选错，后面每一轮规则都在补同一个洞。

2026-09-18 个人资料归档项目，同一个洞栽了四次：

| 轮次 | 我加的规则 | 用户的反馈 |
|---|---|---|
| 1 | 按**文件类型**过滤（课程资料不进） | "跟我有关没多少" |
| 2 | 补**归属权**（含他人姓名的不收） | "获奖也是错的离谱" |
| 3 | 补**流程产物 / 第三方文档**（脚本、通知、模板不收） | "项目作品只有两个？" |
| 4 | 补**结构判据**（没有代码的不算工程） | "llz实习报告明显不是我的" |

根因：**关键词判得出「这是综测表」，判不出「这是**我的**综测表」——同学的综测表文件名结构一模一样。结构判据判得出「这是一个完整工程」，判不出「这是**我的**工程」——`llz实习报告` 有 290 个代码文件，完美通过"完整工程"判据。**
→ **归属类判断，默认答案是问用户；规则只负责把候选做小。**

### 2.5 规则判不了归属时：让人拍板，别把规则调到完美
规则能判的是**类别**，人才能判**归属**。与其一轮轮加规则，不如把形态换掉：

```
脚本按规则把候选做小  →  出一份「可勾清单」  →  用户删行拍板  →  脚本可撤销地执行
```

个人资料归档项目的落地（`索引\make_checklist.py` + `revert.py`）：

- 清单读法：**有的行 = 留，删掉那一行 = 撤收**（`[x]` 是脚本预标记的"已知不要"）
- 撤收分两种：copy 进来的 **删副本**（先断言原件还在）、move 进来的 **移回原处**（先断言原位置空着）
- 落选的一律进 `_重复待删\`，**永不删除** —— 用户改主意可以换回来
- 效果：1827 个文件 → 规则缩到 92 行候选 → 用户一轮砍到 69 个。**比把规则调到完美快一个数量级，而且不会因为猜错而丢东西。**

### 3. 分析参考样本（有就做）
- 要复刻的工具 → 先逆向分析原理再动手（卸载SW项目：MPRESS 解壳 → 摸清 6 步流程 → 复刻）
- 要生成"像官方/像别人家"的输出 → 拿官方模板/开源参考当样本（CC Switch 设计令牌、官方附件5模板）
- 分析结论写进 project.md

### 4. 规则固化进代码
规则、口径、价格、公式全部写进脚本常量表（`calc.py` 常量、`prices.js`、`SKILL.md`），**执行期不重读源文件**（24 页 PDF → 常量表，一次读一次固化）。

### 5. 流水线分阶段
把任务拆成阶段，明确标注每阶段成本，写进 project.md：

```
阶段0 数据就位(人工) → 阶段1 脚本提取(零token) → 阶段2 Claude 处理(⚠️token 大头)
→ 阶段3 脚本计算+回归(零token) → 阶段4 人工核对 → 阶段5 脚本渲染(零token) → 阶段6 交付
```

- 阶段 1/3/5 全用脚本，零 token
- 阶段 2 是唯一大头：**先脚本预提取压缩文本**（xlsx→单元格 dump、docx→文本、pdf→pypdf/OCR、图片→先 OCR），Claude 只读压缩文本（体积 1/50~1/100），OCR 低置信才 Read 原图（视觉输入控制在 <20%）
- 每阶段产出中间 JSON 缓存，官方文件只读一次

### 6. 断点续跑
- 即处理即存（每人/每项一个 JSON 立即写盘），5 个一批分批汇报增量，不重读已完成材料
- 批量操作提供 `--all` 参数，一次跑完只输出每项一行状态
- 重启/中断后从缓存继续，不重新扫描

### 7. 回归断言 + 验证记录表
- 找真值样例（如示例：D1=5.920…总分68.52），写 `--regression` 断言：**逐项相等才进批量，不过不往下走**
- **新功能同样先立断言再实现**：先写出会失败的测试（先看到红灯），再让 AI 做到绿灯 —— 产出不是「看起来能用」，而是有明确验收标准（B站 UP 主接单经验，2026-09）
- project.md 里维护验证记录表：验证项 | 结果 | 日期

**验证六纪律**（2026-09-15/16 桌面挂件项目骗过四次，2026-09-18 归档项目补第五条，2026-10-02 推免材料项目补第六条）：

1. **用物理量，不用状态字段。** `AudioContext.state==='running'` 证明不了出声；`process.getActiveResourcesInfo()` **根本不报告 fs 流**——新旧写法都返回 0，那个测试等于什么都没测。要量就量真正的物理量：音频量输出端 RMS（`AnalyserNode.getFloatTimeDomainData`）、文件句柄量 OS 的 `Get-Process.HandleCount`、内存量 WorkingSet。**指标选错会得到「通过」的假象。**
2. **误报先怀疑测试装置，别急着改代码。** 三次误报全部出在测试而非代码：采样窗口比断言区间晚 0.3 秒；CDP 往返吃掉了 175ms 的短音；气泡停留 5s 而我每步只看 3s，看到的是上一步的残留。**断言要写成「期望的东西出现过」，而不是「某个瞬间我看到了」。**
3. **修复要有 A/B 对照。** 「改完没崩」不算修好——测试期间重启就重置状态。找可量化的对照：同一负载跑旧写法 vs 新写法，149 文件 × 3 轮 → **625 vs 178 句柄**（空跑基准 174），泄漏量 451÷3≈150 ≈ 149 个文件，**一个文件漏一个**；再反推 `8192÷149×60s≈55 分钟`与实测崩溃周期吻合——这才叫证明。
4. **先断言「读到了东西」，再断言内容。** 取样失败会返回空值，而 `''.Contains('x')` 恒为 False——**表现跟「内容确实不对」一模一样**。写 zip 自检时按 `/` 匹配条目名，而 `Compress-Archive` 写的是**反斜杠**，十条检查全部静默假失败，差点被当成「改动没打进包」去返工。**验证脚本开头必须先确认取样成功**（条目数 >0、文件非空、正则命中了），再做内容断言。
5. **验证「结果是否安全」，不只是「动作是否正确」。** 干跑能证明「我会做我打算做的」，证明不了「做完之后系统是安全的」——**干跑全绿也可能在误删**。归档项目里 `--dry-run` 一切正常，但独立写的审计闸门（`audit_plan.py`）发现 **8 个文件会被误删**：它们的重复副本被丢进待删区，而「保留版」因为归属权规则也不进归档，**两边都不留**，内容只剩在用户自己要删的目录里。→ **任何"删除/覆盖/合并"类操作，动手前先证明"替身还活着"**：对每条待删记录，找出所有同内容或同名同类的兄弟，断言至少一个真的进了归档。**这类 bug 不报错，只会安静地少一个文件。**

6. **断言的对象可以是交付成品本身。** 文档 / PDF / 网页每次生成后扫一遍全文：**禁词**（旧数据回潮，如改版后残留的旧版本数字）、**关键事实**（该出现的数据点全在）、**口径词**（不该出现的措辞 / 字符）。与 project.md 的 `<!-- AUTO -->` 块同源——**数字错一处比缺一处更糟**，这类错不报错、只会安静地发出去。

> 那两节是具体案例（Electron、桌宠），只在遇到同类任务时读 —— 每次开局都读一遍是浪费。

### 8. 危险操作先干跑
- 卸载/删除/覆盖类：默认干跑（dry-run）模式，展示将执行的动作，确认后才真执行
- 安全隐患审查：不删用户数据文件（如 Documents 目录、与其他软件共用的 FLEXnet）、密钥不写进代码/文档（config.json 本地保存、注明勿外传）

> 那里面大部分跟当前任务无关，但每次开局都要按整份读进来。
