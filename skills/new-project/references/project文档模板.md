## 收尾检查单（每次交付前过一遍）

- [ ] project.md 已更新（验证记录/待办/限制/更新记录）
- [ ] 回归断言通过
- [ ] 性能改动已跑过基线对比（改前/改后**同规格**采样：同窗口长度、同进程范围）
- [ ] 危险操作已干跑验证过
- [ ] 密钥/隐私未写入代码或文档
- [ ] 可复用资产已登记
- [ ] **交付的交互入口实测过** —— 双击快捷方式、点索引里的链接、双击 `.bat`。**不能只看"文件生成成功"**（归档项目踩过：`.bat` 编码字节级验过但没人双击过；HTML 的「打开」按钮点下去是下载；点「文件夹」把索引页导航走了回不来）
- [ ] **准入/归属类项目**：规则只负责把候选做小，**拍板清单要交用户过目**（别把规则调到完美就交付）
- [ ] 给用户一句话验收说明（怎么用 + 已知限制）

## 附：让 project.md 里的数字可被机器校验

**学自 DSH 插件 Normify 的「结构数据与代码互为契约」。** 动机是自己踩的：
归档项目里手写"138 行（100 归档 + 38 链接）"，实际是 57 + 81 —— **靠人肉对账才发现**。
**文档里写错的数字比不写更糟 —— 下次会照着错的数做判断。**

做法一句话：**磁盘是源数据，文档里的数字是派生数据。**

````markdown
<!-- AUTO:BEGIN —— 由 索引\check_doc.py 生成，别手改 -->
| 项 | 值 |
|---|---|
| 归档实体文件 | 57 |
| 索引条目 | 138（归档 57 + 链接 81） |
<!-- AUTO:END -->
````

配一个 `check_doc.py`：从磁盘重算这几项，跟 `<!-- AUTO -->` 块比对，不一致就报错退出 1；
`--update` 直接改写该块。**这是 §7「回归断言」的一个特例：断言的对象是文档本身。**

配套原则（同样来自 Normify 的"只存 parent，children 派生"）：
- **同一个数字只在一处**。人读的目录树里**不要写计数**，只写形状；计数全放 AUTO 块。
- **手写的结构树一定会和磁盘分叉** —— 要么机器生成，要么只写形状不写数量。
- 脚本里必须带 **断言 0**：`如果量到的项数 < 5 或总数 == 0，直接报 FAIL` ——
  空集合上的断言恒真，等于什么都没测。

## 附：交付"点一下能用"的入口

- **优先给 xlsx**：Excel/WPS 的 `=HYPERLINK("D:\...","打开")` 是把路径交给系统，
  点一下直接用 Word/Excel 打开。网页做不到这一点（见下）。
- **网页里的本地链接有两个坑**（归档项目实测）：`.docx/.xlsx` 会被浏览器**下一份副本**；
  `file:///目录` 会让浏览器**导航走**去显示自己的列表（用户："回不到索引网页了"）。
  正解：注册自定义协议（`HKCU\Software\Classes\<名字>`，不需要管理员、可完全还原），
  让 Windows 而不是浏览器接手，**浏览器不发生导航**。
- **交互入口要实测**：双击快捷方式、点索引里的链接、双击 `.bat`。
  **"文件生成成功"不等于"点了能用"。**
