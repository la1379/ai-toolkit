# bili-learn：B站收藏集 → 学习待办

把 B 站收藏集里的视频，流水线变成「可消化、可追踪、增量更新」的学习条目。本文件是操作手册；**记忆中枢在项目里**（`bili-learn/project.md`），上下文纪律：先读索引，按需下钻，别整库扫。

## 依赖与边界（先看这条）

- 依赖：`@xzxzzx/bilibili-mcp`（搜索/字幕）、Node.js（零 token 脚本）、B 站 Cookie。
- 不适用：不下载或搬运受版权保护的视频；不做批量账号操作；0 星清理必须人工确认、可撤销、永不自动执行。
- 目录布局可按自己的习惯改；§3 只是默认值，改完要同步改脚本里的路径。

## 0. 开工第一件事（读取纪律）

1. 读 `~/My_Skills/INDEX.md`（每条一行，≈几十 token，**先读它**）
2. 读 `~/bili-learn/project.md` 的「口径决策 / 待办 / 防臃肿规则」区
3. 要动某条目 → 只读那条文件夹里的 README；全量操作 → 只跑脚本看摘要，不读快照全文
4. `日志.md`（历史层）只在追溯时读；`project.md` 只读现状，不追历史

## 1. 处理一条视频（标准流程）

1. **定位 & 拿素材**（按 §4 路线选）：
   - 用户没给链接、只报标题 → MCP `search_bilibili_videos` 按标题关键词搜（实测首条命中，样板 BV1cZ8x6sEhF）；搜不到再要链接
   - 工具/项目类（有开源仓库）→ 简介拿仓库链接 → clone 读 README/AGENTS/SKILL → 视频可跳过
   - 课程/长教程类 → `get_video_transcript` 抓字幕，**先跑相关性体检**
   - ⚠️ **字幕相关性体检**：转录文本必须与标题/简介有关键词交集；不通过 = 按无字幕处理（B站 AI 字幕会语义错配，实测把 STM32 视频配成英雄联盟解说）
   - ⚠️ **他人标注不可信**：计划书/清单里配的「为什么做/怎么操作」常是凭标题的猜测（实测：猜成《动手学深度学习》，实际是《高性价比人生指南》生活决策书）→ 先核实视频本体，**不得照抄标注干活**
   - 无字幕且值得要 → 记「待 ASR」（本地 ASR 需 MCP ≥1.14.2 + setup 模型，还没启用）
2. **提级别建议**：给出「建议级别 + 一句理由」，**级别由用户拍板**；判不准进 `00_Inbox\`
3. **按级别产出**（见 §2 表）
4. **写回**：条目 README 首部「一句话（面板/待办用）」→ `INDEX.md` 追加一行 → 跑自升级三动作「学/剪/查」（§5）

## 2. 四级体系（口径定稿 · 2026-10-12）

| 星 | 对象 | 产出 | 完成标准 |
|:--:|---|---|---|
| 0 | 娱乐/游戏/短剧/杂谈 | 无产出，进「清理候选清单」 | 从收藏夹删掉（**改账号动作：批量确认、可撤销、永不自动**） |
| 1 | 工具/资源（下载器、环境配置） | `01_Tools\`，装好能跑 | 用它跑通一个真实任务 |
| 2 | 方法论/思路/行情 | `02_Insights\` 一句话笔记 | 能用一句话复述 |
| 3 | 硬核技术（课设/竞赛/毕设相关） | `03_Hardcore\<名>\` 三件套：README(含完成度自检) + cheatsheet + prompt_skill | 能复现、能改参数、能讲清楚 |

## 3. 锚点路径（别猜，照抄）

- 知识库：`~/My_Skills/`（00_Inbox / 01_Tools / 02_Insights / 03_Hardcore / 04_Archive + INDEX.md）
- 车间：`~/bili-learn/`（project.md=现状 / 日志.md=历史 / scripts/ / data/ ← 缓存区，可删可重建）
- 凭证：`~/.bilibili-mcp/config.json`；报 COOKIE_EXPIRED → `node ~/.bilibili-refresh/refresh.js run`（exit 2 → `init` 重新扫码；**改凭证后需重启会话**）
- 零 token 脚本：`fav_inventory.js` 收藏夹全量快照｜`check_subtitle.js` 字幕体检｜`probe_favs.js` 规模探查。脚本放在车间 `scripts/`，不随仓库分发。
- MCP：`@xzxzzx/bilibili-mcp` 现 1.9.0；**1.14.2 才有收藏夹遍历工具 + 本地 ASR 兜底**（升级命令已备好未执行：全局 npm install -g + 重启会话；⚠️ npm 走 npmmirror 源，直连卡死见坑池）

## 4. 素材路线速查（实战验证过）

- **工具/项目类**：简介 → 仓库 → 三文档 → 三件套。视频字幕可跳过（样板：STM32_AutoDebug工具链）
- **开源书/资源类**：搜标题定位 → 字幕/简介认项目名 → GitHub 搜项目名（中文+英文都试）→ 拉 README 给入口（在线版 / PDF / release / 自带 skill），视频内容可跳过（样板：《高性价比人生指南》= life-decision-guide）
- **方法论/文风类**：字幕提炼模式清单 → 用清单回扫产出文本 → 落到对应 skill（样板：BV1WfJr6kE6H → shuorenhua-slop）；知识成品可落 `02_Insights` 一句话笔记
- **课程/长教程类**：字幕 + 相关性体检；长课按分P/章节切块；无字幕押后 ASR
- **娱乐杂谈**：直接 0 星候选，不提炼
- **收藏夹扫描**：一律走自家脚本（零 token 一次跑完）；MCP 的收藏夹工具是调用方驱动分页（20 条/次），批量场景烧上下文，留给单条交互用

## 5. 自升级协议（每次处理完必跑——"自动进化"的真身 = 学 + 剪 + 查预算）

**A. 学**（进规则层，**先提议、用户确认后才写**）：

1. **有口径被纠正？** → 改本文件 §2/§3 或 `references/口径与坑.md`
2. **有新坑？** → 追加坑池一行（带日期）
3. **重复动作第二次出现？** → 固化成脚本进车间 `scripts\`（零 token 优先）

**B. 剪**（维护四层不膨胀，**自动执行、改完告知**）：

- 合并同类项 / 删过时（过期时效事实、被证伪内容）/ 压细节（过程细节只进 `日志.md`，不进现状层）

**C. 查预算**（写回后立即检查，超了**当场剪**，不许赊账）：

| 层 | 文件 | 预算 | 读取时机 |
|---|---|---|---|
| 规则 | 本文件 SKILL.md | ≤150 行 | 加载 skill 时 |
| 案例 | `references\口径与坑.md` | ≤30 行 | 按需 |
| 现状 | `project.md` | ≤80 行 | 每次会话开场 |
| 历史 | `日志.md` | 不限（一行一条、只增不压） | 追溯时才读 |

只增不减的系统必然膨胀——**学只管长，剪/查管代谢，缺一不可**。

改动规则层后 grep 全库对账死链。
**副本纪律：本 skill 单一来源（`~/.agents/skills/bili-learn`），不做副本；要分发就写同步脚本（new-project 曾漏同步 3 周，引以为戒）。**

## 6. 节奏与边界

- 一批一汇报（增量处理，别一次吞几十条）；每条即处理即存
- 收藏夹增量：重跑 `fav_inventory.js` → 与快照对比 `fav_time` → 新增进待办
- 缓存区（data\）随便删，资产区（My_Skills\）谨慎动；备份只备份资产区
