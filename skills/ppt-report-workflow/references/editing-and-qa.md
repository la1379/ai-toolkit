# 模板编辑与交付兼容性

在沿用 PPTX、单页重做或出现导出差异时阅读。具体 API、验证命令与运行时路径以当前环境文档为准，不硬编码其他机器的路径。

## 导入后的检查

导入工具可能把组合形状展开、重新分配标识符，或改变母版继承关系。先读取检查结果并查看实际渲染，再编辑。

- 不假定页面数组下标、对象内部 ID、检查工具返回的稳定 ID 可以混用。
- 删除元素前确认它属于当前页，还是共享母版或版式。
- 复制页面后重新检查对象标识符，不沿用另一页的旧 ID。
- 区分真实内容与透明框、背景形状、占位符，避免误删背景或留下模板示例字。
- 确认原始页面尺寸，不凭“看起来是宽屏”直接创建另一种比例。

## 保留用户完成的页面

先尝试正常导入、编辑和导出。若未改的页面发生不可接受的变化，定位变化来自字体、分组、布局继承还是导出器。

只有常规工具不能可靠保留时，才考虑复制原生页面或修复 OOXML 包。操作范围应尽量小，并验证：

- 页面、版式、母版、主题、图片、备注和字体的关系目标完整。
- 页面顺序、关系 ID 和内容类型正确，无悬空或重复引用。
- 不同验证器或软件是否要求惯用的页面目录结构。
- 原页的超链接、动画等实际需要保留的功能是否仍然存在。

涉及图表、嵌入工作簿或复杂动画时，不要把简单图片页面的拼接脚本当通用合并器。已有可靠的原生复制或文件接口时优先使用。

仅当确实要求未改页完全保真时，才进行额外的字节或像素比较。它们也不能证明页面内容本身准确。

## 字体与文件体积

沿用参考文件实际使用的字体，并核对字体可用性、字重与中英文显示。不要在导入警告出现时立即更换整套字体，也不要忽略目标软件中的明显替代字体。

参考文件把字体嵌进包内而本机并未安装时，字体可以从文件里取回，不必换成替代字体。解包后字体部件位于 `ppt/fonts/`，`fntdata` 前面带一段混淆头，真实字体从 sfnt 签名开始（`OTTO` / `0x00010000`，个别成品在签名前还有一层包装）；从签名处截取到文件末尾即得字体文件。取回后按容器内引用的族名写回名称表再安装，族名与引用对不上时目标软件仍会替换字体。安装前用字体工具确认字重与名称，只装本机缺少的那几个。

中文字体嵌入可能占用大量体积。单页文件仍异常大时，检查是否带入了整套材料的未用字体、图片或母版。只在确认资源未被需要的页面引用时清理，并重新验证。不要为减小文件牺牲中文字形或编辑能力。

中文标点行首、英文缩写断词和数字单位分离，应先检查文本框宽度、语言和断行设置。必要时调整句子或在自然语义处换行。不要把手动逐字断行当作跨软件稳定排版的默认方法。

## 两种验证各自负责什么

| 验证 | 能发现的典型问题 | 不能据此声称 |
|---|---|---|
| 文件结构与对象检查 | 页数、关系损坏、缺失图片、部分越界和不可编辑对象 | 内容真实、布局美观 |
| 逐页视觉检查 | 拥挤、意外断行、图片失真、标题层级和视觉重点 | 所有业务事实准确 |
| 目标软件检查 | 字体替换、实际行距、表格和图片兼容差异 | 所有其他软件也完全一致 |

最终检查应针对真正交付的文件。修改候选文件后重新导出或验证，不能用旧版本的截图给新文件背书。若最终化工具只做无损复制，可以用文件哈希确认交付件与已检查候选件一致。

有可用的目标软件时，以只读方式检查，不覆盖用户原件，不关闭用户其他窗口或进程。检查通过后停止无目的的反复微调；若仍有影响使用的差异，明确说明，而不是笼统声称“兼容无误”。

用目标软件做自动化检查时，让它全程留在后台，不设置可见窗口——把应用设为可见会反复夺走焦点，打断用户正在进行的操作。检查结束后关闭文档并退出程序；残留的进程会让下一次调用失败，报错信息通常只是“服务器执行失败”，容易误判成环境权限问题。脚本类文件按目标环境的编码保存，含中文时注意编码声明，否则报错信息本身就会变成乱码。
