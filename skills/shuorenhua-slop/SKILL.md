# AI 垃圾文风避雷清单（本地补充）

这份清单是本地补充，不属于官方 2.6.0 的默认规则。只在用户明确要求时启用：

- “避雷”
- “按 AI 垃圾文风清单检查”
- “把 AI 腔清干净”
- “严格去 AI 味”

用户只说“去 AI 味”“说人话”“自然一点”时，不启用本清单，按官方 `shuorenhua` 的默认规则做最小编辑。

## 先划保真红线

改写前先划出不能动的内容：

- 事实、判断、谁做什么、数字对应什么
- 条件、范围、否定、情态、完成状态、比较关系
- 术语、命令、路径、接口名、代码、引用原文
- 承诺、可核查的排名与首次、效果幅度、作者评价
- 责任归属和原文已有的下一步

清单里的模式只触发检查，命中不等于删除。每条都有保留条件。改写不能新增原文没有的事实、数字、来源、功能或操作步骤。

## 1. 卖点堆叠 / 定语堆山

**识别**：一个能力被拆成一组 `可 X / 有 X / 支持 X` 的并列标签，或者用数字对仗撑气势。

```
❌ 可编辑、可定制、可追溯
❌ 有表情、有动作、有脾气
❌ 一个程序，几十种命令
❌ 一次部署，到处运行
```

**处理**：只留真正有区别、能落到动作或数字上的那一项。需要列功能时列具体能力，不列 `可 X` 形容词。数字没有来源就删数字，不换一个更像真的数字。

```
✅ 每次改动都会记一条操作日志，可以按时间或用户查
✅ 它会按你说话的语调换表情
✅ 配置文件在 ~/.tool/config.toml，换机器复制过去就能用
```

**保留**：正式功能清单，每一项都是可核验的独立功能；接口文档里的真实属性（`可编辑`、`只读`）；用户明确要的营销文案；引用原文。

## 2. 微型小剧场

**识别**：一个动作或条件被写成有主角、有先后、有反应的微型叙事。

```
❌ 你一点击，它立刻回应
❌ 只要打开开关，它就会立刻开始同步，不用手动刷新
❌ 用户一打开页面，系统马上自动加载数据
```

**处理**：压回动作或条件本身。删掉多余的 `你 / 用户`、`立刻 / 马上` 和重复的反应描述。

```
✅ 点击回应
✅ 打开开关后开始同步
✅ 打开页面时加载数据
```

**保留**：时延、动画时长、反馈状态、失败分支、复现步骤本身是规格；小说、剧本、口播稿；用户明确要求场景化说明。

## 3. 否定递进

**识别**：先否定一个东西，再肯定另一个，用对比制造洞见感。常见骨架：

```
❌ 不是 X，而是 Y
❌ 与其 X，不如 Y
❌ 就像一个 X，而不只是一个 Y
❌ 真正的 X 不是 A，而是 B
```

**处理**：直接说 Y。Y 本身有信息量时保留 Y，删掉前半句的否定骨架。

```
✅ 管理流程比代码本身更容易出问题
✅ 体验细节决定它能不能长期被用下去
```

**保留**：前半句承载必要的边界、风险或反例；对比本身是论证骨架，删掉后后文的数据或结论会失去依据；术语定义；引用原文。单句正常对比可以保留，同段密集出现才处理。

## 4. 防御性免责声明

**识别**：用户没有问范围、风险或替代关系，文本先主动划边界。

```
❌ 这只是修改系统功能，不是重做整个系统
❌ 这个工具不能当成万能方案，也不意味着可以替代人工审核
❌ 仅用于 X，不适用于 Y
```

**处理**：删掉防御性否定骨架。真实限制写成条件或动作。

```
✅ 这次只改登录接口的错误提示，其他模块不动
✅ 工具只做初筛，命中后仍要人工复核
```

**保留**：法律、医疗、金融、安全场景的正式免责声明；误用会造成实际损失的限制说明（`此接口只读，不写入`、`该操作不可撤销`）；用户明确询问范围或风险；引用原文。

## 5. 总分对仗 / 数字承诺

**识别**：用结构性对仗把简单能力说成一套体系，数量往往没有来源。

```
❌ 一个 X，多个 Y
❌ 一次 X，N 种 Y
❌ 一次配置，多处生效
```

**处理**：直接说做了什么、得到什么。数字必须有来源，没来源就删掉数字。

```
✅ 配置改一次，所有环境共用
✅ 这个命令会同时更新三个文件：a、b、c
```

**保留**：数字有来源且与对象对应；正式规格说明；用户明确要求的总分结构；引用原文。

## 6. 吃定心丸 / 未经请求的安心承诺

**识别**：用户没有表达担心，文本主动补控制权或安全保证。

```
❌ 主动权始终在你手里
❌ 随时可以修改 / 停止 / 回退
❌ 不用担心，不会影响你的数据
```

**处理**：删掉安抚层。控制权确实相关时，写成具体操作或条件。

```
✅ 调用 stop() 停止任务；已处理的文件保留
✅ 删除后 30 天内可从回收站恢复
✅ 这个操作只改缓存，不动原始文件
```

**保留**：法律或平台要求的安全提示；不可逆、破坏性操作前的真实警告；用户明确表达担心；新手引导里控制权就是说明重点；引用原文。

## 输出与回读

- 用户要求“先标问题，不改写”时，只列问题点：触发句、命中的模式、建议动作、是否建议改写。
- 默认只交一份改写稿，不附命中清单和评分。
- 回读先查保真：事实、数字、条件、否定、情态、承诺、责任主体有没有丢或变。
- 再查残留：还有没有卖点堆叠、小剧场、否定递进、防御性免责、数字对仗或安心承诺。
- 不为了避雷把文本改得更假、更短或更空。删完没有剩内容时，直说原文没有可保留的正文。
